MOPPy ON ARE

From model output to CMORised data

Your existing MOPPy workflow, with a place to prepare and follow every batch.

1. Configure a batch

Load batch_config.yml from a Gadi path or upload it from your computer. Adjust metadata, paths, variables and PBS resources in the builder. Use the YAML editor for advanced settings. Choose a new output directory for every submitted batch.

2. Review the job

Preflight checks the configuration, accessible paths and installed MOPPy interface, resolves a dated analysis3 runtime, and saves the YAML plus native monitor script. Check the project, storage mounts, parent lineage and executable worker setup before submitting.

3. Follow the work

MOPPy's PBS monitor submits the variable jobs and writes its tracking database. Studio reads that database and shows per-variable states, errors and log tails. Progress is the percentage of variables completed, not an estimate of remaining time. The selected run refreshes every 15 seconds.

Existing runs and recovery

Attach a batch's output folder to monitor it without changing its files. If submission times out, Studio retains an uncertain state and offers a PBS lookup; it never automatically repeats qsub. Missing scheduler history is shown as unknown. This beta does not retry or cancel batches; use MOPPy and PBS tools for those operations.

Scientific checks

Preflight does not establish complete input coverage or scientific correctness. MOPPy validates and processes the actual data in the variable jobs. Start with a bounded run, inspect its output and enable relevant QC. Explicit file patterns and auxiliary paths need the corresponding ARE and batch storage mounts.
